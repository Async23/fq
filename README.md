# fq

`fq` 是 macOS 的终端版“强制退出应用”：输入一条命令，在原生 TUI 中筛选普通 GUI 应用，选择一个或多个应用并确认后退出。

它不依赖 `fzf`，也不是 `btop` 的进程列表换皮。应用范围来自 macOS 的 `NSWorkspace`，并只保留系统标记为 `.regular` 的应用，因此更接近 `Cmd + Option + Esc` 所展示的“应用”，而不是所有 Unix 进程。

## 安装

需要 macOS 13 或更新版本，以及 Xcode Command Line Tools。

```sh
cd ~/code/demo/fq
make install
```

默认安装到 `~/.local/bin/fq`。如果这个目录已在 `PATH` 中，随后可直接运行：

```sh
fq
```

## 使用

```sh
fq                         # 选择应用，确认后强制退出
fq safari                  # 打开时先按 safari 筛选
fq --quit                  # 请求正常退出，相当于应用级 Cmd-Q
fq --list                  # 非交互地列出应用
fq --json code             # 以 JSON 列出匹配 code 的应用
```

选择器采用 Vim 风格操作：`j` / `k`（或 `↓` / `↑`）移动，`h` / `l`（或 `←` / `→`）在智能、应用名、PID、状态排序之间切换，`r` 反转当前排序，`u` 暂停或恢复实时列表。按 `Space` 标记或取消标记当前应用，标记行显示 `✓`，底栏显示已选数量。

批量选择不需要逐行点完：按 `v` 从当前行开始范围选择，用 `j` / `k` 扩展或收缩，再按 `v` 或 `Space` 保留范围，按 `Esc` 撤销本次范围。`a` 标记当前筛选下的全部可见应用，`i` 反选可见应用，`x` 清空全部标记。范围选择期间列表顺序会暂时冻结；结束后立即接回最新应用快照，并按进程身份保留仍然有效的标记。

`t` 打开正常退出确认，`K` 打开强制退出确认，`F1`、`?` 或 `H` 查看帮助，`q` 关闭。

`f` 或 `/` 进入筛选，范围包括应用名、Bundle ID 和 PID。Vim 按键和 `Space` 只在浏览态生效；筛选态会把它们作为普通文本输入。浏览态不会把其他普通字符或粘贴内容误当成搜索词或退出操作，并会提示先进入筛选。筛选态会把整段粘贴作为一次编辑插入，其中的换行和连续空白会折叠为单个空格。

鼠标也遵循终端列表的选中逻辑：滚轮移动列表视口，单击一行定位，再次点击同一行标记或取消标记；列表溢出时，右侧会显示 `↑` / `↓` 和单格滑块，点击箭头翻页、点击轨迹跳转，也可以按住滑块拖动。滚动时会让当前选择留在原来的屏幕行，并且滚动条事件不会误触发退出动作。标题栏、底栏的可见命令以及确认时的 `y` / `n` 都可以点击。已有筛选旁的“del 清除”也可点击。退出 fq 时会恢复终端的鼠标模式。

按 `Ctrl-Z` 或从外部发送 `SIGTSTP`，都会先恢复终端鼠标、光标和原屏幕，再把 fq 挂起到后台；运行 `fg` 后会回到原来的筛选或确认状态，并先刷新一次应用快照。正常取消和退出会恢复终端状态；收到外部 `SIGINT`、`SIGTERM`、`SIGHUP` 或 `SIGQUIT` 时，也会先恢复终端，再按原信号退出。

默认的智能排序会优先显示 macOS 当前的前台应用，并在筛选时按匹配度排列；切换排序或反向时，当前选择会继续绑定原进程，不会跳到排序后的相邻应用。

筛选框采用 btop 式单行编辑：`←` / `→` 和 `Home` / `End` 移动光标，`Backspace` / `Delete` 分别向后或向前删除，`Ctrl-U` 清空。按 `↓` 会应用筛选并移到下一项，`Enter` 只应用筛选。`Esc` 或筛选中的鼠标点击会恢复进入编辑前的筛选词和所选应用；若该应用期间已经退出，则选择停在原行附近，不会跳回列表首项。

`Enter` 打开标题栏所示的默认动作（默认是强制退出，`--quit` 时是正常退出）。存在标记时，`Enter`、`t` 或 `K` 会对所有标记应用执行同一个动作；没有标记时只操作当前行。批量操作会逐个处理，即使某个应用失败也会继续；当前前台应用会最后处理，避免先退出承载 fq 的终端而中断其余目标。

确认不会再切到居中的按钮式对话框，而是保留原应用列表、当前行和所有 `✓` 标记：顶栏显示待执行动作及目标数，状态行显示风险，底栏只显示 `y 执行 │ n/Esc 返回`。按 `y` 执行；按 `n`、`Esc`、`Enter`、`Space` 或 `Backspace` 返回，因此默认仍然不会误执行。终端高度或宽度不足时会压缩为同样的 `y/n` 命令提示。在浏览态，`Home` / `End` 和 `PgUp` / `PgDn` 可快速移动，`Delete` 或 `Ctrl-U` 清空已有筛选，`F1`、`?` 或 `H` 打开选择器内帮助。

所有退出动作都在全屏选择器内确认，直接按 `Enter` 或 `Esc` 会返回应用列表。强制退出会显示未保存内容风险；Finder 会显示专门的“将由 macOS 自动重新打开”提示。

应用列表会在选择器中自动刷新，并按进程身份保留当前选择和标记。如果部分批量目标在确认期间退出，fq 会明确显示跳过数量，并只处理仍然存在的目标；如果全部目标均已退出，则停用确认动作，不会把操作转移到相邻应用。

暂停只冻结屏幕中的应用列表；fq 仍会在后台记录最新快照，并用它检查确认目标是否仍然存在。恢复时会立即应用最新列表，因此暂停不会放宽退出前的进程身份校验。

完整参数见：

```sh
fq --help
```

## 它会显示哪些应用

`fq` 枚举 `NSWorkspace.shared.runningApplications`，只显示 `activationPolicy == .regular` 的运行中应用：

- 会显示普通桌面应用，包括隐藏或没有可见窗口的普通应用。
- 不显示 shell 命令、守护进程和大多数仅菜单栏/后台应用。
- macOS 没有提供稳定公开的“应用未响应”列表接口，因此 `fq` 不声称能复刻系统窗口中的“未响应”标记。

执行退出前，`fq` 会再次核对 PID、Bundle ID 和启动时间。如果原进程已经退出、PID 被复用或身份发生变化，它会取消操作，而不是向新进程发送退出请求。

## 开发

```sh
make format       # 格式化 Swift 源码
make check        # 格式检查、测试、Release 构建
```

代码分成三个模块：

- `FQCore`：命令行解析、候选应用模型、模糊匹配和选择状态。
- `FQMacOS`：AppKit 应用枚举/退出适配器、终端选择器和命令编排。
- `fq`：极薄的可执行入口。

这种边界让纯逻辑无需启动 AppKit 或真实终端即可测试，同时把 macOS 与终端细节封装在内部适配器后面。
